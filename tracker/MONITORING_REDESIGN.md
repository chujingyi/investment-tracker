# 监控中心重构方案

状态：设计草案，确认后实施  
范围：个股监控、板块信号、宏观事件  
原则：监控中心负责提醒和行动，不承担完整研究报告功能

## 1. 设计目的

监控中心服务于“用户无法持续盯盘”的场景，核心回答三个问题：

1. 最近发生了什么重要变化？
2. 现在是否需要采取行动？
3. 为什么提醒，下一步应观察什么？

系统不应因为价格每天变化而重复打扰用户。只有状态变化、临近重要节点、正式触发、信号失效或需要复盘时才提醒。

## 2. 信息架构

监控中心分为三个层级：

| 标签 | 层级 | 主要内容 | 典型周期 |
|---|---|---|---|
| 个股监控 | 微观 | 价格条件、持仓状态、公司事件 | 数日到数月 |
| 板块信号 | 中观 | 板块趋势、轮动、产业链、主题拥挤度 | 数周到半年 |
| 宏观事件 | 宏观 | 利率、通胀、就业、政策与重要日历 | 数日到半年 |

页面顶部增加统一的“需要关注”摘要，只汇总三类监控中发生状态变化的项目。

近期和远期不是独立页面，而是每个标签内部的时间维度：

- 近期：未来 30 天或数周级技术条件
- 远期：30 天以上或季度级趋势

## 3. 统一监控状态

三类监控尽量共享以下状态：

| 状态 | 含义 | 是否提醒 |
|---|---|---|
| tracking | 正常监控，条件尚远 | 否 |
| approaching | 接近触发条件 | 首次进入时提醒 |
| triggered | 条件成立，等待用户确认 | 是 |
| revalidate | 数据或原逻辑发生变化，需要复核 | 是 |
| invalidated | 信号已失效 | 是 |
| snoozed | 用户暂时忽略 | 到期后提醒 |
| archived | 已结束或已归档 | 否 |

提醒采用状态变更驱动。相同状态没有新证据时，不重复发送提醒。

## 4. 个股监控

### 4.1 展示范围

个股监控页面默认只展示：

- 推荐记录为 `active`
- 明确开启 `monitoring`
- 数据仍在有效期内
- 最新行情没有过期

已止盈、止损、停止、卖出或归档的记录不再出现在当前监控列表中。

### 4.2 触发类型

价格条件必须明确区分：

- 回落买入：价格向下进入目标区间
- 突破买入：价格向上突破确认位
- 止损预警：跌破失效位
- 止盈预警：进入目标区间
- 重新评估：价格变化超过原假设范围

不能继续使用统一的“当前价小于等待价即触发”逻辑。

### 4.3 价格不等于结论

价格到达等待价后，状态只能先进入 `triggered` 或 `revalidate`，不能直接显示“可以买”。

至少还要检查：

- 原投资逻辑是否仍成立
- 是否有新的财报、公告或行业事件
- 行情数据是否新鲜
- 是否出现放量破位
- 用户是否已经买入或卖出

### 4.4 自动退出规则

- 推荐状态不再为 `active`
- 用户已卖出且没有继续观察意图
- 超过有效期
- 连续多个交易日深度越过失效条件
- 标的退市、停牌或数据长期不可用

### 4.5 有效期

建议默认值：

- 短线：30 天
- 中线：90 天
- 中长线：180 天
- 长线：按季度复核，不永久静默保留

### 4.6 数据新鲜度

- 超过一个交易日未更新：显示“数据过期”，禁止触发行动提醒
- 刷新失败：保留旧值，但明确标记更新时间和错误
- 线上持仓与推荐记录不一致：进入 `revalidate`

## 5. 板块信号

### 5.1 页面定位

“板块信号”位于个股监控与宏观事件之间。它是中观提醒层，不是完整行情终端。

已有“轮动雷达”继续承担详细分析；监控卡提供摘要并链接到轮动或板块详情。

### 5.2 一张板块卡显示

- 板块名称
- 监控周期：近期 / 中期 / 远期
- 当前状态
- 与上次相比发生的状态变化
- 最多三条触发原因
- 建议动作
- 上次检查时间、下次检查时间
- 详细依据入口

详细均线、量比、成分股和历史数据默认折叠。

### 5.3 AI 基础设施示例

监控对象：

- 行业代理：SOXX、SMH
- 龙头确认：NVDA、TSM
- 可扩展观察：AVGO、MU、ASML、AMAT、ANET、VRT、ETN

首版条件：

1. SOXX 与 SMH 守住动态 60 日均线
2. 连续 2–3 个交易日不再创新低
3. 下跌成交量收缩
4. NVDA 与 TSM 出现相对强势并企稳
5. SOXX 与 SMH 重新站回 5 日或 20 日均线

满足至少三项时进入 `triggered`，提示可考虑第一批 20%–25% 试仓。单日反弹不能触发。

### 5.4 后续可扩展板块

- 半导体
- AI 基础设施
- 核电与电力
- 医疗
- 金融
- 工业与自动化

板块配置应由数据或管理配置产生，不能为每个板块写一个专用页面。

### 5.5 提醒规则

- `tracking → approaching`
- `approaching → triggered`
- `triggered → invalidated`
- 关键条件发生明显变化
- 长时间无变化时只进入周报摘要

## 6. 宏观事件

### 6.1 命名与范围

监控中心原“催化剂”标签改为“宏观事件”。但原有数据不能简单整体改名，必须拆分：

#### 个股事件

- 财报
- 分红
- 拆股
- 公司公告

这些事件跟随个股监控展示。

#### 板块事件

- 云厂商资本开支
- 行业财报季
- 产业链政策
- 供需与产能节点

这些事件跟随板块信号展示。

#### 宏观事件

- FOMC 与央行讲话
- CPI、PCE、非农、GDP
- 财政、监管和产业政策
- 重要地缘事件

只有这一类进入“宏观事件”标签。

统一日历可以叠加三类事件，但必须使用不同颜色、类型和来源标签。

### 6.2 当前已有来源

- 长桥财经日历：财报、分红、拆股、IPO、休市
- 手动录入：FOMC、非农、央行讲话、主题节点
- `macro_events` 数据表：目前未完整接入页面
- 财报同步接口：目前需要手动触发，只覆盖活跃推荐标的
- 市场日历接口：访问页面时获取，未持久化，不产生主动提醒

### 6.3 目标来源

| 来源 | 内容 | 优先级 |
|---|---|---|
| 长桥 | 财报、分红、拆股、IPO、休市 | 高 |
| 美联储官方 | FOMC、会议纪要、主席讲话 | 高 |
| BLS | CPI、PPI、非农、失业率 | 高 |
| BEA | GDP、PCE | 高 |
| 手动维护 | 主题、政策、产业链特殊节点 | 必需 |

外部来源必须保存：来源名称、来源链接、外部事件 ID、抓取时间、最后校验时间。

### 6.4 更新规则

- 每日同步未来 180 天事件
- 每周完整校验一次
- 使用“来源 + 外部事件 ID”去重
- 检测日期变化、取消与新增
- 已过期事件自动转为“待复盘”或归档
- T-7 与 T-1 提醒
- 事件发生后生成待复盘任务

### 6.5 事件状态

- scheduled：已确认
- changed：日期或内容发生变化
- imminent：七天内发生
- happened：已发生，待评估
- reviewed：已复盘
- cancelled：取消
- archived：归档

## 7. 页面样式统一

三类标签统一使用：

- 状态徽标
- 标题 + 周期 + 更新时间
- 状态变化摘要
- 最多三条原因
- 建议动作
- 展开详情

颜色语义统一：

- 红色：需要立即处理或风险失效
- 黄色：接近触发、需要确认
- 绿色：条件成立
- 灰色：正常观察
- 蓝色：信息或日历事件

列表、卡片、空状态、加载状态和错误状态使用统一组件。页面上方与下方不再分别使用完全不同的表格和卡片体系。

## 8. 数据模型方向

建议逐步引入通用模型，而不是继续给各功能追加零散字段：

### monitor_definitions

保存监控定义：类型、名称、周期、条件、刷新频率、是否启用。

### monitor_states

保存当前状态：状态、分数、摘要、最后检查时间、数据版本。

### monitor_events

保存状态变化记录，用于通知去重和历史复盘。

### calendar_events

统一保存个股、板块和宏观事件，并保留来源与外部 ID。

首期实施可以兼容现有表，先增加适配层，不一次性迁移全部历史数据。

## 9. 更新与部署方式

当前生产目标是阿里云 ECS + Docker Compose，不使用 Vercel Cron。

建议：

- Web 容器负责页面和手动刷新
- 独立单实例 worker 负责定时同步
- 两者共享 Turso 或持久化数据库
- 避免在 Gunicorn 多 worker 内启动定时器，防止重复执行

任何部署动作必须在本地实现、测试、展示并得到用户确认后执行。

## 10. 测试隔离

测试必须强制使用临时 SQLite，禁止自动读取生产 Turso 配置。

要求：

- 测试启动时覆盖数据库连接
- 测试结束自动删除临时库
- 外部行情接口使用 mock
- 集成测试与生产数据完全隔离

## 11. 实施顺序

### 阶段一：清理基础问题

1. 隔离测试数据库
2. 清理价格监控展示条件
3. 修复回落与突破方向判断
4. 增加数据过期与有效期规则
5. 统一监控页面基础样式

### 阶段二：板块监控

1. 增加通用板块监控卡
2. 接入 AI 基础设施首个监控定义
3. 状态变化记录与提醒去重
4. 链接轮动雷达详情

### 阶段三：宏观事件

1. 将原催化剂按个股、板块、宏观分类
2. UI 改名为“宏观事件”
3. 接入未来事件自动同步
4. 增加来源、变更检测与事件后复盘

### 阶段四：阿里云部署

1. 本地完整测试
2. 提供页面预览和改动清单
3. 用户确认
4. 提交与推送
5. 用户再次确认后部署到阿里云
6. 验证 worker、数据库和提醒状态

## 12. 验收标准

- 已停止或已结束的个股不会出现在当前监控中
- 过期行情不会生成行动提醒
- 回落与突破条件判断正确
- 板块信号只在状态变化时提醒
- AI 基础设施监控可以解释每个触发条件
- “宏观事件”只包含真正的宏观事件
- 个股和板块事件进入各自页面
- 未来事件能够自动新增、更新、取消和去重
- 每条外部事件显示来源与最后更新时间
- 页面三部分的状态、颜色和卡片样式一致
- 测试不会连接或写入生产数据库
